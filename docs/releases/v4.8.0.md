# CARD v4.8.0 — 2026-11-14

> Big minor release on top of v4.7.0: 43 first-parent merges (PRs #207–#256). Twenty-three new feature records
> (FR-131, FR-133, FR-135–FR-165), covering governance (separation of duties, versioned period run, native approval
> workflows, approval tiers, approval delegation without role grants, workflow state guards), privacy (money fields
> on Card Monthly Card hidden from Card Operator and CARD Mobile), diesel (per-hour rate precedence, fill allocation,
> variance report, operating group, **Diesel Dispense → draft Stock Entry with tanks as Warehouses, off by default**),
> billing (credit note for non-taxable deductions, day billing basis per equipment), transport (keep intake evidence
> of submitted transports, child-row cross-document guard, parent permlevel on child-table reads), mobile (daily log
> screens for operators), portal scaffold (off by default), Marketplace packaging (declared Frappe range).
> Multiple new idempotent data patches, several new submittable DocTypes, no CARD GL write anywhere (FR-100 preserved
> throughout). Every new rule that could refuse existing work is **opt-in per company** or **warn-only**; the changes
> that are on by default are listed in section 9.
> Labels: **Verified / Partially Verified / Unknown / Not Supported / Deprecated / Removed**.

## 1. Version Overview

v4.8.0 collects the work merged to `main` between the v4.7.0 release (`be73af2`) and `e34c7dd` (PR #256,
`chore/step0-release-readiness`). Main themes, by area:

- **Governance (first):** separation of duties on the monthly card submit (FR-143); versioned Card Period Run with
  accountant approval (FR-147); native approval workflows, created inactive (FR-152); child-row cross-document guard
  (FR-153); posting requires an approved period run (FR-154); workflow state guards + bypass suite (FR-155);
  approval tiers + authorization rule note (FR-159); money privacy on Card Monthly Card (FR-162, owner O-20); approval
  delegation without role grants (FR-163, owner O-12).
- **Diesel:** per-hour rate takes precedence over the daily figure (FR-144); variance and anomaly report (FR-151);
  fill allocation rows (FR-157); operating group + diesel group analysis report (FR-160); **Diesel Dispense → draft
  Stock Entry with tanks as Warehouses, off by default** (FR-164, owner O-11 D1); effective-dated consumption rates
  with type default and equipment override (#223); snapshot price currency / unit / valid-from on each fill (#209).
- **Billing & credit:** credit note for non-taxable customer deductions (FR-156); day billing basis per equipment
  with submit snapshot (FR-138); per-company transport responsibility posting, Hold by default (FR-139); sided
  downtime billable reasons (#212).
- **Transport & intake:** keep intake evidence of submitted transports (FR-146); intake provenance and source-key
  dedupe (also FR-146, first wave); enforce parent permlevel on child-table reads (FR-148); card day provenance
  (FR-158); refuse child rows that belong to another document (FR-153).
- **Equipment:** Card Reviewer role granted to nobody (FR-137); equipment meter readings with monotonic engine hours
  (FR-140); dated Card Rate Agreement with `resolve()`, opt-in and unwired (FR-141); Card Daily Log with manager
  approval (FR-142; cancel-change guard added in #226).
- **Settings & permissions:** generic company-scope hooks for the planned DocTypes (FR-131); scope Card Settings
  company rows to the user's companies (FR-133); materials warehouses and repeat window per company (FR-135);
  acceptance suite + Posting Source Integrity report + report currency label (FR-136).
- **Mobile:** daily log screens for operators (FR-150, mobile side).
- **Portal (scaffold):** party portal off by default (FR-161, owner O-16 deferred to O2's PR).
- **Packaging:** Frappe Marketplace compliance metadata; declared Frappe range `>=16.50.0,<17.0.0` (FR-165; the
  CARD CI and Upgrade rehearsal gate runs on frappe 16.55.2 / erpnext 16.54.0).
- **Documentation:** full documentation site (#229), issue triage (#230), registry sync (#232), site screenshots sync
  (#240), What's new + README overhaul (#241, #242), deployment v4.7.0 recorded (#219), release readiness pack
  (#256 — Frappe range declared, logo added, gitleaks allowlist, FR-164 valuation risk documented).

Why a minor version: new features and new DocTypes, no removed API, no breaking schema change. The behaviour changes
that apply by default are listed in section 9.

Previous version on Production: **v4.4.3** (`688eb71`, last recorded in
[DEPLOYMENTS.md](DEPLOYMENTS.md)). v4.5.0, v4.6.0 and v4.7.0 have no recorded Production deployment. A deployment of
v4.8.0 to a site on v4.4.3 also brings the changes of [v4.5.0](v4.5.0.md), [v4.6.0](v4.6.0.md) and
[v4.7.0](v4.7.0.md); their setup actions and rollback limits apply too.

## 4. Improved

- **FR-144:** rate resolution now resolves to the per-hour rate when both per-hour and daily are configured — the
  per-hour rate takes precedence; the daily-only path is unchanged for equipment without a per-hour rate.
- **FR-146:** transports keep their intake evidence after submit; intake provenance records source and source key; a
  repeat submission from the same source with the same key is refused on the way in.
- **FR-148:** child-table reads inherit the parent's permlevel (defence in depth beyond the DocType JSON).
- **FR-131, FR-133:** generic company-scope hooks and Card Settings row scoping cover every planned CARD DocType.
- **FR-155:** workflow state guards + a bypass suite make bypass approvals explicit and audited.
- **FR-157, FR-158, FR-160:** diesel fills carry allocation rows, card days carry provenance, and equipment
  groups surface in diesel analysis.
- **Documentation site:** every documented screen has English + Arabic screenshots; Reference section is generated on
  every build.

Full list per FR: [CHANGELOG `[4.8.0]` section](../../CHANGELOG.md#480--2026-11-14) → `### Added` and `### Changed`.

## 5. Fixed — Partially Verified

- **Security — FR-148 (#227):** child-table reads now enforce the parent DocType's permlevel. Before the fix, a user
  without level-1 read on the parent could read permlevel-1 child rows through a Report Builder on the child
  DocType. Shown by `test_bola_matrix.py` and `test_child_permlevel.py` (CI); on a site: **Unknown** until the
  post-deploy check.
- **Security — FR-153 (#238):** child rows now refuse to belong to another document; a `parent` or `parenttype`
  forged at save time is dropped and the save is refused. Shown by `test_child_parent_guard.py` (CI); on a site:
  **Unknown**.
- **FR-146 (#228):** intake evidence of submitted transports is kept (previously the file could move on cancel +
  amend). Shown by `test_transport_intake.py` (CI at frappe 16.55.2; a few tests fail on frappe < 16.55.0 where
  the File delete protection hook is not available — see Known Limitations).
- **FR-144 (#239):** per-hour rate precedence correctly resolves against both legacy and v16 rate tables.
- **FR-142 (#226):** Card Daily Log refuses a cancel that changes the stored log (previously the cancel could
  silently rewrite the log).

## 9. Breaking Changes — Verified

No API is removed and no data is changed by the release. These behaviour changes apply **by default** (on every site
on migrate; no opt-in required):

- **FR-148 — parent permlevel enforced on child-table reads.** A user without level-1 read on the parent DocType no
  longer sees permlevel-1 child rows through Report Builder on the child DocType. Users with level-1 read on the
  parent are unaffected. Existing records are not changed. Verified in `card/permissions.py` at `deebd29`.
- **FR-153 — child rows refuse to belong to another document.** A forged `parent` or `parenttype` on save is dropped
  and the save is refused. Users and existing records are not affected in normal use (the client never sends these
  values). Verified in `card/child_parent.py` at `e83b2e2`.
- **FR-146 — intake evidence of a submitted transport is kept.** On cancel + amend, the file stays attached to the
  cancelled transport; a new amended transport attaches a fresh evidence file. Users who relied on the evidence
  moving to the amended record must re-attach it. Existing attachments are not moved. Verified in
  `card/transport_intake.py` at `98be5fd`.
- **FR-137 — Card Reviewer role exists but is granted to nobody.** No user gains or loses access on migrate; the owner
  grants the role explicitly.
- **FR-144 — per-hour rate precedence.** Equipment with BOTH a per-hour and a daily rate now resolves to per-hour.
  Existing postings are not changed; future rate resolutions use per-hour first.

Warn only by default (a message, the save goes through) — opt-in per company to Refuse:

- **FR-154 — posting requires an approved period run** (opt-in per company via
  `period_run_required_before_posting` default `Off`; Warn or Refuse modes).
- **FR-155 — workflow state guards** (opt-in per company via `workflow_bypass_rule`).
- **FR-159 — approval tiers** (opt-in per company via `enable_approval_tiers` default `0`; thresholds in
  `approval_tier_thresholds`).

Off by default (opt-in per company):

- **FR-164 — Diesel Dispense + tanks as Warehouses** (opt-in per company via `enable_diesel_tanks` default `0`;
  flag off = behaviour unchanged, the direct-fill flow `Project Diesel Fill` is untouched).
- **FR-161 — party portal scaffold** (opt-in per company via `enable_party_portal` default `0`; every portal URL
  returns 404 for every viewer until the flag is on **and** O2 wires routes).
- **FR-139 — transport responsibility posting** (Hold by default).

On-by-default for Card Operator / CARD Mobile role only (defence in depth; no current reader loses visibility):

- **FR-162 — money privacy on Card Monthly Card.** Ten Currency fields and one child `amount` move to permlevel 1;
  four new permlevel-1 DocPerm rows grant read to the four current level-0 readers (System Manager, Card Manager,
  Card User, Accounts Manager). Card Operator and CARD Mobile portal roles are not granted level-1 read and so
  never see amounts in a future route that might expose them; the print format already guards the money rows with
  a Jinja helper.

## 10. Known Limitations — Verified

- **Published ≠ deployed.** Deployment of 4.8.0 to any site is a separate, site-verified fact (section 14).
- **FR-164 valuation risk (documented in the FEATURE-REGISTRY row and in the module docstring):** a fresh fuel tank
  with no valuation history inserts the draft Stock Entry with `allow_zero_valuation_rate = 1`; the accountant
  must set the real `basic_rate` before submit (or seed the valuation through a receipt) — otherwise the GL expense
  posts at zero. FR-100 is still preserved either way.
- **FR-164 semantic choice:** the Stock Entry purpose is `Material Issue` (consumption; no target warehouse), not
  `Material Transfer` (owner-approved 2026-11-14). A future owner decision to switch to Material Transfer would
  need a per-company "diesel consumption warehouse" setting.
- **FR-161 party portal is scaffold only.** Every portal URL returns 404 for every viewer until WP-O2 (later wave)
  adds the website routes + `has_website_permission` hook AND the owner grants read on Card Monthly Card to the
  Supplier and Customer roles on his explicit approval (owner decision O-16, deferred to O2's PR). The documentation
  site's "What's new" entry frames this honestly as scaffold (Lesson 13).
- **FR-146 under frappe < 16.55.0:** the File delete protection hook that keeps the intake evidence requires frappe
  16.55.0 or newer. CI runs on 16.55.2 and the hook works; a site on frappe 16.54.x sees the test
  `test_transport_intake.py` fail three cases (the fix is ineffective there — the file can still be deleted on
  cancel + amend). Upgrade to frappe ≥ 16.55.0 to get the full behaviour.
- **FR-141 Card Rate Agreement is unwired.** The DocType and the `resolve()` helper exist and are opt-in; no runtime
  caller invokes `resolve()` yet. Rate resolution continues to read from `Card Rate` / equipment fields.
- **FR-152 native approval workflows are created inactive.** No DocType switches to workflow-driven approvals until
  the owner activates them explicitly per DocType.
- **FR-165 Marketplace listing is not published.** Metadata is in place; the listing itself needs owner action
  (owner approval + Marketplace submission) and has its own open items (Terms of Service / Privacy Policy pages do
  not exist yet; logo is above the 200×200 minimum but no English brand wordmark).
- **FR-148 class residual (upstream Frappe):** `frappe.get_all` for a few fields on the new DocTypes shares a class
  of upstream residual not yet closed; owner decision 2026-11-10 is to wait for the upstream Frappe fix.
- Everything listed in [v4.7.0 section 10](v4.7.0.md#10-known-limitations--verified) still applies, except any item
  explicitly superseded above (FR-007 money hiding is superseded by FR-162).

### 12.2 Migration

`bench --site <site> migrate` runs the patches above, syncs the DocType JSON (adding the new DocTypes and the new
settings fields), and applies the custom-field / fixtures if any. No data row is modified. Run `migrate` twice to
prove idempotency.

### 12.3 Rollback

- **Published tag `v4.8.0` is immutable.** Rolling back a deployment means pinning the site to v4.7.0 (or earlier).
- **Previous version compatible with v4.8.0 data:** v4.7.0 can run on the migrated data because every v4.8.0 change
  is additive (new DocTypes, new fields with defaults, new settings with safe defaults). New DocTypes become
  orphaned but inert; new fields on existing DocTypes carry their defaults. Submitted documents in the new DocTypes
  (Card Daily Log, Card Period Run, Card Approval Delegation, Diesel Dispense, Equipment Meter Reading, Equipment
  Operating Group) are not visible under v4.7.0 code but remain in the database.
- **Restore plan:** `bench --site <site> restore <backup.sql.gz>` from the pre-upgrade backup, then re-run migrate
  against v4.7.0 code. See `docs/releases/RELEASE-POLICY.md` for the full safe-rollback checklist.
