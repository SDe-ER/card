# CARD v4.3.0 — 2026-11-09

> Minor release on top of v4.2.2: integrity guards and project/equipment cost allocation for CARD monthly postings,
> transport cost responsibility with a financial decision, three read-only reconciliation and review reports and a
> transport accounting review, Card Equipment financial privacy, a night-shift customer rate, an A4 supplier
> statement, and the portal catalog fix for ERPNext v16.54.0+ (Company Restriction). No new patch; new columns by
> DocType sync. It has breaking changes (section 9), as v4.1.0 did, under the owner's decision to keep a minor
> version.
> Labels: **Verified / Partially Verified / Unknown / Not Supported / Deprecated / Removed**.

## 1. Version Overview

CARD postings get two accounting controls. A posting draft is signed when it is built, and a draft edited after
that cannot be submitted (an Accounts Manager may accept a corrected cost center or account with a reason).
Supplier invoices booked by hand for the same month must be linked to their CARD sources or declared unrelated
before a build. Each posting line now carries the cost center of the project or assignment, never the company
default. Equipment Transport records who pays the transporter and who finally bears the cost. A recharged move
waits for an Accounts Manager's financial decision. Four read-only reports (diesel invoices, transport
accounting, hour meters, Asset mapping) support review. The financial fields of Card Equipment are visible only
to System Manager, Card Manager and Accounts Manager. A machine rented to a customer can have a night-shift rate.
This is also the first CARD version whose portal catalog works on ERPNext v16.54.0 or later (Company Restriction).
Sites that update ERPNext to 16.54.0 or later need 4.3.0.

## 9. Breaking Changes — Verified

1. **Equipment Transport (FR-093).** `responsibility` is required and `cost_borne_by` no longer defaults to
   Company. Draft transports saved under v4.2.2 need `responsibility` (or `payer` + `cost_bearer`) before their next
   save or submit. External or REST clients that create or save transports must send those fields: a v4.2.2
   payload without them is refused. No patch fills them in. CARD Mobile does not create transports.
2. **Card Equipment field privacy (FR-096, FR-097).**

   | Field | Level before | Level now | Who reads it now |
   |---|---|---|---|
   | `cost_center` | 0 | 2 | System Manager, Card Manager, Accounts Manager |
   | `asset_cost_center` | 0 | 2 | System Manager, Card Manager, Accounts Manager |
   | `asset_purchase_value` | 0 | 2 | System Manager, Card Manager, Accounts Manager |
   | `internal_hourly_rate` | 1 | 2 | System Manager, Card Manager, Accounts Manager |
   | `approved_hourly_rate` | 0 | 1 | System Manager, Card Manager, Card User, Accounts Manager; no longer Card Supervisor |

   Card User and Card Supervisor lose read of the level-2 fields (Card Supervisor never had level 1, so it did not
   read `internal_hourly_rate` before either), in the form, the REST API, list and report
   queries and exports. Card User can no longer set the equipment cost center. `card.api.get_asset_prefill` and
   `card.api.create_equipment_from_asset` return only the fields the user may read. New Version records of Card
   Equipment keep who changed a restricted field and when, not its values.
3. **Posting integrity (FR-090).** Posting drafts built before 4.3.0 must be rebuilt before submit. For a
   VAT-registered supplier, an empty `diesel_price_vat_basis` on Card Company Settings refuses the build.
4. **Cost allocation (FR-091).** A build is refused when a cost center is missing, unusable (group, disabled, other
   company) or conflicting, and for every company-paid move to or from a project.

The API keeps its endpoints and arguments: `create_equipment_from_asset` gains optional `ownership` and `save`
only, and without them inserts nothing (as before).

## 10. Known Limitations — Verified

- **Published ≠ deployed.** No site runs 4.3.0 yet.
- Customer transport invoicing, supplier recovery documents, Purchase Invoice posting of P1-2 transports, tax
  treatment and account mapping are disabled on purpose (FR-093).
- The monthly build still has no Desk button (FR-004).
- Existing Card Equipment Version records are not changed (FR-096).
- The four new reports are read-only. The meter reconciliation sets no maintenance baseline. A diesel period
  difference is a point to review, not a confirmed over-billing or missing payment.
- A4 supplier statement: choose Landscape in the PDF dialog.
- FR-076: real ERPNext catalog integration in a browser is still unverified (as before).

## 12. Installation & Upgrade — Partially Verified

`bench --site <site> migrate` runs no new patch (`card/patches.txt` unchanged since v4.2.2). It syncs the
DocTypes: new nullable columns on Card Company Settings (`diesel_price_vat_basis`), Card Equipment
(`customer_rate_night`), Equipment Transport (responsibility, payer, cost bearer, cost project and the financial
decision fields) and GL Posting Log (signature, acceptance, review and link-difference fields); new field levels on
Card Equipment; four Script Reports, one Report Print Format and the Card Reports sidebar. It writes no value to
existing transports, cards, fills, postings, logs or settings, and no GL entry.

After migrate, before the first build: set `diesel_price_vat_basis` per company with VAT-registered diesel
suppliers; check project and assignment cost centers; rebuild posting drafts built before 4.3.0; give every draft
transport its responsibility; update any external client that writes Equipment Transport.

**Rollback statement — Unknown (safe old-code run not proven).**

- Last stable version: **v4.2.2**.
- Schema: v4.2.2 code can run on the migrated database after a `bench migrate` with that code. The new columns are
  nullable and stay unused, and no patch since v4.2.2 wrote data (there is none).
- Data created under 4.3.0 is not safe for v4.2.2 (checked in `git show v4.2.2:card/gl/posting.py` and
  `equipment_transport.py`):
  - Every transport saved under 4.3.0 has an empty `cost_borne_by`. v4.2.2 takes every submitted, not yet invoiced
    transport with an empty `cost_borne_by` into the transport supplier's monthly build as a company-paid move,
    so a recharged move would be posted as a company cost. This does not fail closed. The safe failure described
    in the CHANGELOG holds for the P1-0 code (`main` before PR #154), not for v4.2.2.
  - The signature and link checks of FR-090 are gone: drafts built under 4.3.0 could be submitted without them.
    How v4.2.2 treats linked GL Posting Logs is Unknown.
  - Draft night-shift cards take the day customer rate again on their next save. Submitted cards keep their stored
    values.
  - The v4.2.2 field levels return, so Card User and Card Supervisor read the financial fields again. New Version
    records carry their values again.
- Plan: restore the pre-upgrade backup (database and files), but only while no transaction has been made after it.
  Otherwise fix forward with a 4.3.x patch. Checking out v4.2.2 restores code only.
