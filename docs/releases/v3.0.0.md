# CARD v3.0.0 — 2026-10-19

> Major release on top of v1.2.2. **Not yet tagged**: this page is written in the release PR; the
> tag, release URL and merge commit are added to Evidence when the tag is pushed. The CHANGELOG
> section is dated 2026-10-19 (the content cut date). The version jumps from 1.2.2 to 3.0.0 by owner
> decision ("CARD Unified UX" design named it 3.0.0); no 2.x release exists.
> Labels: **Verified / Partially Verified / Unknown / Not Supported / Deprecated / Removed**.

## 1. Version Overview

A unified navigation and the first data-flow changes of the "CARD Unified UX" design:

- a **CARD launcher** (frappe `Dock`) with nine entries, each opening its own sidebar;
- **Equipment Transport** moves several machines at once, reads where each machine is now, sends it
  to a project, workshop, storage or back to its supplier, and charges the cost to the destination;
- the **monthly card follows the approved transports** (its project comes from the equipment's
  assignments in that month);
- an owned or managed machine takes its **details from its ERPNext Asset**;
- **dated unit components** (replace / move a piece with history).

## 3. Added — Verified

- **CARD launcher**: `Dock` rows Dashboard, Equipment, Movement & Transport, Operating Units,
  Operation Cards, Expenses, Suppliers & Customers, Reports, Settings; each opens a sidebar of
  existing documents and reports (Operating Units = equipment marked as units; Expenses adds
  Purchase Invoice and Asset Repair). Tests: `card/tests/test_v3_navigation.py`.
- **Multi-machine transport**: equipment table, equal cost split with editable shares that must add
  up to the trip cost; submit moves every machine, cancel reverses each; one posting line per
  machine share on the equipment dimension.
- **Destinations and automatic From**: destination Project / Workshop / Storage (ERPNext
  `Location`) / Supplier (rented only); From is read from the open assignment, else the last
  approved non-project move, else Storage (first move); a move to where the machine already is is
  refused; workshop/storage/supplier moves end the project assignment on the transport date.
- **Cost bearer**: Company (transport supplier invoice, as before), Equipment Supplier (no cost),
  Customer (recorded, not invoiced). Only Company-borne moves reach postings and cost reports.
- **Destination cost center**: the destination project's cost center, or the workshop/storage
  cost center per company in Card Settings (`Card Location Cost Center`); a supplier return stays
  on the project it leaves.
- **Monthly card follows transports**: project filled and locked from the month's assignments; one
  card per project when the machine moved mid-month; a machine staying on a project gets a card
  every month and shift; only eligible days are offered (a unit: only days every piece is on the
  project). GET `get_card_context` (record read checked).
- **Company operators**: owned or company-operated equipment picks an Employee operator; a rented
  machine with the lessor's operator keeps a typed name.
- **Equipment from its ERPNext Asset**: Asset field next to ownership (owned and managed); picking
  it fills name, image, cost center, custodian as operator and insurance (GET `get_asset_prefill`,
  record read checked). The name, the Asset item's brand and the type mapped from the Asset
  category (new *Asset category* on the equipment type, one category per type) follow the Asset on
  every save and are read-only; empty brand/model/year/chassis/plate are hidden.
- **Documents**: the Documents tab comes second; the form warns about documents expired or
  expiring within 30 days.
- **Company auto-fill**: new equipment, transport and diesel forms fill the company when the user
  can list exactly one (GET `get_only_company`); the field stays visible and editable.
- **Dated unit components**: From/To/reason per component; POST `replace_component` and
  `move_component` (level-1 write on components, refused inside an approved card period, piece
  must be on the unit's project).

## 4. Improved — Verified

- Transport and equipment forms carry no field help texts (owner rule: clean forms).
- Each machine's Connections tab lists every trip it was on.
- Unit component integrity on concurrent and direct-row writes (#59, PR #71): direct child-row
  updates are refused; validation takes locking reads.

## 5. Fixed — Verified

- #59 (PR #71) — see Improved.

  touches only assignments of the transport's own machines (unreleased code only; no published
  version affected).

## 6. Removed — Verified

- Typing From/To on a transport: the old free-text fields are hidden and read-only (kept for older

## 7. Replaced

- `covering_assignment` (internal helper) → `month_assignments` / `assignment_projects`.
- Transport header `equipment` → first row of the equipment table (header kept as a mirror).

## 8. Simplified

- Dashboard sidebar reduced to the home page, monthly cards and transports (the rest moved to the
  launcher's sidebars).

## 9. Breaking Changes — Verified

- **A monthly card needs an approved transport covering its month.** Equipment without a Card
  Equipment Assignment in the month cannot save a card (new or re-saved draft) until a transport
  records its move. Sites that never used transports must record them before using v3 cards.
- A card's project outside the equipment's assignments is refused (also through REST).
- Equipment linked to an Asset: name, brand and mapped type are taken from the Asset (read-only);
  the upgrade patch renames linked equipment to their Asset names.
- A transport to the project the machine is already on is refused; From/To are not typed.

## 10. Known Limitations — Verified

- Navigation needs frappe `Dock` + app `Sidebar`: verified on 16.51.1 only; other 16.5x minors
  **Unknown**; pre-16.50 **Not Supported** (stay on v1.0.1).
- ERPNext `Asset` has no model, year, chassis or plate fields; for linked equipment they are hidden
  unless already stored.
- Customer-borne transport is not invoiced; dated rate agreements are planned, not shipped.
- Dock tooltips stay English (frappe core).
- Some older CARD forms still show field help texts.
- Published ≠ deployed: **not deployed to any production site**. Production's frappe version must
  be checked on the site before any upgrade.

## 12. Installation & Upgrade — Partially Verified

- Fresh install: README → Installation.
- Upgrade from v1.2.2: `bench migrate` runs `v3_0_0.backfill_transport_items` and
  `v3_0_0.sync_equipment_from_asset` once each (post-model-sync, idempotent; no GL entry, invoice or
  card amount written). Verified on the dev site: migrate twice, no duplicates.
- After upgrade: set workshop/storage cost centers in Card Settings, map Asset categories to
  equipment types, and record a transport for every working machine before its next card.
- **Rehearse on a copy of production first.** Rollback = restore the pre-upgrade backup (no
  down-migrations).

## 13. Recommended For

- New installs on frappe 16.51+ that want the launcher, transport-driven cards and Asset-linked
  equipment.
- Sites that already record equipment moves (or can record them before the first v3 month).
- **Not** for sites that cannot record transports yet (cards would be blocked) — stay on v1.2.2.
- Not for pre-16.50 frappe (v1.0.1).
