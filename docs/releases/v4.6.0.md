# CARD v4.6.0 — 2026-11-10

> Minor release on top of v4.5.0: the wave-2 merge train (19 feature, fix, CI and documentation pull requests, plus
> five documentation and dependency pull requests without user impact: #136, #148, #149, #166, #204). Three new data patches, two new DocTypes,
> new columns on eight DocTypes, four new per-company settings. Every new rule that could refuse existing work is
> warn-only or off by default; the changes that are on by default are listed in section 9.
> Labels: **Verified / Partially Verified / Unknown / Not Supported / Deprecated / Removed**.

## 1. Version Overview

v4.6.0 collects the work merged to `main` between the v4.5.0 tag (`1b7c20d`) and `8ededce` (PR #194), with the
registry sync of PR #204 (`14ce454`). Main themes:

- **Security:** read endpoints GET-only and diesel fill company isolation (FR-098), attachment validation and
  privacy (FR-099), reviewer is not the approver on equipment needs (FR-121).
- **Governance:** mandatory cancel reason and a reviewable period-lock override (FR-123), dead settings retired
  without deletion (FR-124).
- **Equipment:** owned-only combined units and a derived component flag (FR-115), initial place (FR-116), move-day
  rule (FR-117) and equipment status guard (FR-122) per company.
- **Downtime:** configurable stop reasons, the responsible party of a stopped day and the Equipment Downtime report
  (FR-118).
- **Diesel:** project-tank diesel posts at project level (FR-100), effective-dated price schedule (FR-125), project
  check of the filled equipment (FR-126), optional meter extraction through a local worker (FR-101), re-check of
  photos when a rejected fill returns to review (FR-085).
- **Transport:** costs the company does not pay and an "other party" responsibility (FR-120).
- **Accounting and analytics (read-only or unchanged posting):** CARD Monthly Posting page with a side-effect-free
  preview (FR-119), Equipment Partial Margin, Unbilled Card Work and Equipment Maintenance Cost reports
  (FR-112 to FR-114), card values on the CARD workspace (FR-111).

Why a minor version: new capabilities and new optional settings; no API is removed. Behaviour changes that apply
by default are intentional owner decisions and are listed in section 9.

Previous version on Production: **v4.4.3** (`688eb71`, last recorded in [DEPLOYMENTS.md](DEPLOYMENTS.md)). v4.5.0
was published but has no recorded Production deployment, so a deployment of v4.6.0 also brings the v4.5.0 changes
([v4.5.0.md](v4.5.0.md)).

## 9. Breaking Changes — Verified

No API is removed and no data is deleted. These behaviour changes apply **by default** (owner decisions recorded in
the CHANGELOG):

- FR-098: six read functions refuse POST, PUT and DELETE; cross-company read, write and share of a diesel fill are
  refused.
- FR-099: a save with a non-allowed, oversize, undecodable, public or another record's file is refused (HEIC photos
  are refused).
- FR-100: open draft CARD postings built before this release that hold a project-tank fill are refused on submit
  until rebuilt.
- FR-115: a rented or third-party equipment cannot become a unit or join one; ownership of a unit or listed piece
  cannot change away from owned; the component flag is no longer a manual tick.
- FR-121: whoever reviewed, edited or submitted an equipment needs review cannot approve it (Administrator and System
  Manager included).
- FR-123: every cancel of a Card Monthly Card, Equipment Transport or Project Diesel Fill needs a reason; Frappe's
  "cancel all linked documents", an active Workflow's cancel action and the List view bulk cancel are refused for
  these doctypes.
- FR-125: after the seed patch every company with a diesel price has a schedule row, so its `diesel_unit_price` is
  read-only; a price change is a new dated schedule row.
- FR-111: the number card "مبالغ الشهر الماضي" now shows the supplier `net_amount` (with additions and deductions)
  instead of `amount`.

Warn-only by default (a message, the save goes through): FR-122 equipment status, FR-126 diesel fill project check.
Unchanged by default: FR-116 (empty place), FR-117 (next-day rule, as before), FR-118 (no billable reason), FR-101
(worker off).

## 10. Known Limitations — Verified

- **Published ≠ deployed.** Deployment of 4.6.0 to any site is a separate, site-verified fact (section 14).
- FR-098 (#161): an external client that calls one of the six GET-only read functions with POST is refused.
- FR-099 (#162): HEIC photos are refused (save as JPEG); a financial re-decision that keeps an older unattached
  transport document is refused (upload it again); with one unattached upload saved on two records at once, only the
  first claims the file. Files already stored as public stay public (owner decision pending).
- FR-100 (#163): rebuild open drafts built before this release; tank diesel moves from the equipment assignment's
  cost center to the fill's or the project's, so cost-center and equipment-dimension reports around the release are
  not month-to-month comparable; the GL equipment dimension no longer includes tank diesel.
- FR-101 (#164): off unless the two site_config keys are set; the worker URL must be an IP literal (loopback for
  `http`, loopback or private for `https`); expect most real photos to need a person; a full queue or unreachable
  Redis skips the extraction for that save (no retry).
- FR-111 (#185): users without read access to the level-2 rate fields see "N/A" on the internal cards; the internal
  value needs `internal_rate` on owned and managed equipment.
- FR-112 to FR-114 (#188): revenue and maintenance need the Card Equipment accounting dimension (FR-031; missing on
  Production per records) and costs tagged with it; depreciation, labour, insurance and overhead are excluded;
  Asset Repair and journal entries are not read by the maintenance report.
- FR-115 to FR-117 (#187): legacy rented units and ambiguous component flags are only listed (Error Log "CARD unit
  records to review (#42)"), never changed; transports recorded before this release have no move-day rule and keep
  the next-day behaviour.
- FR-118 (#194): the seed covers companies that have cards when `migrate` runs; a company that gets its first card
  later creates its reasons by hand. A billable reason bills both sides. `min_hours` is still not read (FR-020).
- FR-119 (#193): Accounts User read of GL Posting Log is an open owner decision; the page is not on a workspace
  sidebar yet.
- FR-120 (#190): picking an Employee party needs Employee read permission (no role widened).
- FR-121 (#189): another Card Manager or System Manager must approve; a legacy pending review falls back to its
  supervisor or owner.
- FR-122 (#191): Project Diesel Fill is not guarded by the equipment status (follow-up FR-128, PR #200, not in this
  release).
- FR-123 (#197): records cancelled before this release keep an empty reason; a reason, once set, is not editable.
- FR-124 (#198): a write to a retired setting through the API is still stored and still has no effect.
- FR-125 (#195): Card Settings is a Single, so a user who can read level 1 receives the schedule rows of every
  company (the form shows and the server allows only permitted companies). The seed patch lives in
  `card/patches/v4_7_0/` although it ships in 4.6.0 (naming only; Frappe runs patches by their line in
  `patches.txt`).
- FR-126 (#196): Warn only by default; the equipment-status check of fills is a follow-up (PR #200).

### 12.4 Production setup actions (after the deploy, each with the owner's approval)

1. **Card Equipment accounting dimension (FR-031)** — needed by FR-112 and FR-114 (and by CARD posting):
   `bench --site <site> execute card.dimension.ensure_card_equipment_dimension`. It adds a `card_equipment` custom
   field to about 53 ERPNext doctypes; it is not undone by a code rollback. Separate approval and backup.
2. **Per-company settings** in Card Settings > Company settings, for each company row: check or set
   `initial_location` (empty = storage without a place), `move_day_rule` (keep "the day after the move" unless the
   owner chooses the move day), `equipment_status_rule` (keep Warn only, or Refuse), `diesel_fill_project_check`
   (keep Warn only, or Off / Refuse).
3. **Stop reasons seed** — check that each company with cards has the three seeded reasons (billable off); create
   reasons for companies without cards; tick `billable` only on a reason the owner approves (it changes card
   amounts and postings built from them).
4. **Diesel price schedule seed** — check one row per priced company, price equal to its `diesel_unit_price`, valid
   from its earliest fill; later price changes through "Change price" (a new dated row).
5. **Internal rates** — fill `internal_rate_basis` and `internal_rate` on owned and managed equipment (level 2,
   commercial change reason required) for the workspace internal value.
6. Review the Error Log entry "CARD unit records to review (#42)" if the unit patch wrote one.
7. If any CARD draft posting exists, rebuild drafts that hold a project-tank fill before submitting them (FR-100).
8. Keep the meter worker keys absent unless the owner decides otherwise (FR-101).

### 12.6 Rollback plan

**Rollback target:** v4.4.3 (`688eb71`), the Last Verified Production Deployment (no Last Known Good Release is
established, DEPLOYMENTS.md). Changes between the two: CHANGELOG [4.5.0] and [4.6.0] (PRs #182 and those of
section 2).

**Rules:** checking out v4.4.3 restores code only. A database restore is allowed only when no Production transaction
made after the backup would be lost; otherwise the rollback is a forward fix. No rollback, restore or downgrade
without the owner's explicit approval for that action.

**Options, in order of preference:**

1. **Forward fix** (default once users have worked on v4.6.0): switch a rule off in settings (FR-122, FR-126 to
   Warn only / Off; FR-117 back to the next-day rule; untick billable reasons) or ship a v4.6.x fix.
2. **Code rollback to v4.4.3** (`688eb71`): the v4.4.3 code runs on the v4.6.0 database, it ignores the new columns
   and tables. Before the switch (while v4.6.0 still runs):
   - amend transports submitted with "Other party bears the cost" (v4.4.3 refuses that value on a new save, FR-120);
   - cancel or keep transports submitted under the move-day rule (v4.4.3 cancels them only if the old assignment
     ends on the move date, FR-117);
   - keep accounting disabled, or cancel v4.5.0 Journal Entry links (v4.4.3 ignores them, so linked cards count as
     not invoiced, v4.5.0);
   - cards saved with a billable stop reason keep their amounts until saved again or amended (FR-118);
   - drafts built by the new builder keep one project-level tank line (rebuild them on v4.4.3 to get the old split,
     FR-100).

   Steps (placeholders only; each step is followed by its check):

   1. Switch the CARD code to v4.4.3: deploy the kept v4.4.3 image, or in a bench `cd apps/card && git fetch --tags
      && git checkout v4.4.3`. Check: `git -C apps/card rev-parse --short HEAD` shows `688eb71` (bench), and
      `bench version` lists `card 4.4.3`.
   2. `bench --site <site> migrate`. Check: it ends without an error; the Error Log has no new CARD error.
   3. Restart the web and background workers (`bench restart`, or restart the containers of the image deploy). Check:
      the Desk opens and a Card Monthly Card and Card Settings load.
   4. Before users resume work: set each company's `diesel_unit_price` to its current schedule price in Card
      Settings (v4.4.3 reads only that field; the seed did not change it, but later prices live only in the
      schedule, FR-125). This is not possible earlier: v4.6.0 refuses a change of `diesel_unit_price` once the
      company has schedule rows (`card_settings.py` `_validate_diesel_price_schedule`). Check: a new draft fill of
      each company shows the expected price.
   5. Record the rollback in [DEPLOYMENTS.md](DEPLOYMENTS.md).
3. **Full restore of the pre-deploy backup**: only when it loses no Production transaction made after the backup
   (for example a failure during the deploy window before users work), and only with the owner's explicit approval
   for that restore. Steps: switch the code to v4.4.3 as in option 2 step 1, then
   `bench --site <site> restore <backup-database.sql.gz> --with-public-files <backup-files.tar>
   --with-private-files <backup-private-files.tar>`. Check: the restore ends without an error; `bench --site <site>
   migrate` ends without an error; the last document created before the backup is present. Then restart the workers
   (option 2 step 3) and record the restore in DEPLOYMENTS.md.
