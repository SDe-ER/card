## 1. Version Overview

Three targeted fixes on v1.2.0: operational roles can run filtered reports without any ERPNext
permission grant, the monthly-card and diesel/transport prints show the right money on the right
side, and supplier/customer totals keep each side's own additions and deductions.

## 2. Complete Feature Inventory — Verified

Identical feature surface to [v1.2.0](v1.2.0.md) (18 DocTypes, 9 reports, 3 app print formats +
legacy format, Card Settings/roles, diesel & transport, accounting dimension, opt-in draft
postings). Patches: 20 entries (3 new v1.2.1 patches).

## 3. Added — Verified

- Equipment Customer Statement gains **Additions / Deductions / Net** columns (part of #24/PR #27).
- New Arabic strings for the relabelled money fields.

## 4. Improved — Verified

- Supplier/customer registry rows now exist from a party's **first draft card** (backfilled on
  migrate) and follow ERPNext Supplier/Customer renames and merges (PR #22).

## 5. Fixed — Verified (CHANGELOG `[1.2.1]`)

- **Filtered reports for operational roles** (#21, PR #22): Frappe v16 validates report Link-filter
  values against the user's own read/select permission, so a Card User could not filter by
  supplier, customer or project. Supplier/customer filters now link to the CARD registries; Company
  and Project are CARD-scoped Autocomplete filters; master Link columns the user cannot read return
  as plain text. No ERPNext permission is granted to any Card role.
- **Monthly card print** (#25, PR #26): each billed side prints its own invoice figures (supplier
  `amount → net_amount`, customer `customer_amount → customer_net_amount`); sub-rental prints both
  sides and names the customer; a rented-out card with a 1,200 customer deduction printed
  "net due 0.00" and now prints 6,000; the supplier total box prints the gross under a gross label;
  the Arabic mixed bold/regular overlap on the adjustments line is gone.
- **Diesel fill and transport prints** (#25, PR #26): money fields labelled «قيمة التعبئة» /
  «تكلفة النقل» instead of core's «كمية»; amount-in-words labelled «المبلغ كتابةً» with ر.س instead
  of the ISO code. No core translation overridden.
- **Supplier and customer totals keep each side's adjustments** (#24, PR #27): supplier
  registry/reports no longer fold customer-side rows of sub-rental cards into the supplier net;
  the customer side uses the customer net (what the Sales Invoice bills) instead of the gross.

## 6. Removed

None.

## 7. Replaced — Verified (breaking for custom clients)

- Internal whitelisted Link-query endpoints `card.api.card_projects_query` and
  `card.api.card_companies_query` → **replaced** by `card.api.card_project_options` /
  `card.api.card_company_options` (Autocomplete contract). A custom client calling the old names
  must switch.

## 8. Simplified

None recorded.

## 9. Breaking Changes — Verified

- Only the endpoint replacement above. No field removed or renamed; only the labels of `amount` on
  Project Diesel Fill / Equipment Transport change. The default monthly-card print format stays
  "Card Monthly Card Print"; an existing site-level default is not overwritten.

## 10. Known Limitations — Verified

- **Multi-company registry isolation unresolved (#23, open at this tag — fixed in v1.2.2):**
  registry rows and their stored totals are per party across all companies; do not rely on them on
  a multi-company site at this version.
- Reconciliation difference compares card nets **before VAT** with VAT-inclusive party GL totals,
  so it does not reach zero for VAT-registered parties (pre-existing; refined into three separate
  figures in v1.2.2).
- Legacy print format «كارت تشغيل شهري» keeps pre-existing wkhtmltopdf layout defects
  (**Deprecated** in practice — use "Card Monthly Card Print").
- Amount in words uses the company's default currency (single-currency sites).
- Published ≠ deployed: not deployed to any production site.

## 12. Installation & Upgrade — Verified

- From v1.2.0: `bench --site <site> migrate` runs three idempotent patches in order:
  `backfill_customer_net_amount`, `ensure_party_registries`, `recompute_party_registries` — they
  write only the derived card column and CARD registry rows; no submitted accounting document is
  touched. A party whose recompute fails is logged in Error Log and counted in migrate output.
- Compile translations (`bench build` or `bench compile-po-to-mo --app card --force`) and
  `bench --site <site> clear-cache`, otherwise new labels show in English.

## 13. Recommended For

  audit/permission surface — prefer it. Not for pre-16.50 Frappe (Unknown).
