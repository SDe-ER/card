## 12. Installation & Upgrade — Partially Verified

- **Upgrade from v4.14.2:** new code; `bench --site <site> migrate`; `bench --site <site> clear-cache`; restart. No
  `bench build` (no `public/` or `frontend/` change). Rebuild the compiled translations: the spelling change reaches
  a site only with them.
- **Checked from source:** `git diff v4.14.2..HEAD -- card/patches.txt card/patches '*.json' card/hooks.py
  card/fixtures card/public frontend` shows no file. No patch, no DocType JSON, no fixture, no hook, no `public/`
  file and no `frontend/` file changed. The application changes are two DocType scripts and the locale files.
- **How the scripts reach users.** Neither script is an asset file. Frappe adds the text of `<doctype>.js` to the
  form meta as `__js` and the text of `<doctype>_list.js` to the same meta as `__list_js`
  (`FormMeta.add_code`, `frappe/desk/form/meta.py`, `version-16`). The Desk gets that meta when it opens a form or a
  list. In production the meta is held in the client cache under the key `doctype_form_meta::<doctype>`, and
  `frappe.clear_cache()` empties it. So the scripts need `bench --site <site> clear-cache`, which the upgrade steps
  already run, and a reload of the Desk in each browser. They need no `bench build`.
- **What migrate writes:** nothing of this release. **It does not write:** any column, document, amount, GL entry,
  role or permission. No Workspace record is written.
- **Post-deployment acceptance (owner):** reload the Desk once. Open an Equipment Transport in Arabic and check that a
  read-only place of type Workshop shows `ورشة صيانة`.
- **Safe rollback — Verified from source; not runtime-tested.** Code only, to v4.14.2, and compile the locale files
  again. No data step. v4.14.3 writes no new field, state or record type.
