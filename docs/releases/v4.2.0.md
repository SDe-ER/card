# CARD v4.2.0 — 2026-10-27

> Minor release on top of v4.1.2: project diesel fills become metered sessions with meter photos and an
> operations review, reviewed WhatsApp diesel sessions can be imported as draft fills, the catalog shows
> parts fitment, and the application name is CARD in every language. One new idempotent patch; new
> columns and one child table by DocType sync.
> Labels: **Verified / Partially Verified / Unknown / Not Supported / Deprecated / Removed**.

## 1. Version Overview

A diesel fill now records the session evidence: the opening and closing meter photos (private files of
the fill), the readings, the meter's cumulative totalizer readings and the photo times. A closing
reading sets the litres. A Card Manager or System Manager approves or rejects each fill before it can
be submitted. Sessions reviewed from the WhatsApp record can be imported as draft fills on the server
(`bench execute`, not a web endpoint), with the supplier invoice price where the invoice states one.
The release also ships parts fitment in the catalog search (phase 2b), the app name CARD in every
language, and a guard that stops a backdated transport from dropping submitted card days.

## 9. Breaking Changes — Verified

## 12. Installation & Upgrade — Verified

`bench --site <site> migrate` runs the patch `card.patches.v4_1_3.remove_app_name_translations` and
syncs the DocTypes (new columns, new child table). A second migrate changes nothing.

Rollback: v4.1.2 code runs on the migrated database (it ignores the new columns and the child table).
A removed Translation can be restored from its Deleted Document; or restore the pre-upgrade backup.
