# Localization matrix

Principle (#40 principle 3): global multi-company, multi-currency, multi-language, multi-country and tax compatible,
with no hardcoded currency, workflow or tax rule. This file records what the code does today for each dimension, and
where it is still tied to one country or language. Sources: `card/locale/`, `card/print_utils.py`, `card/fonts.py`,
`card/constants.py`, `card/gl/*.py`, `card/settings.py`, DocType JSON.

Status: **Ready** (works for any company by configuration), **Partial** (works, with a stated limit), **Local**
(built around one locale; works elsewhere only by accident), **Planned** (issue number).

## 2. Reading the table

- "Ready" rows are covered by tests named in the row or in [07-international-test-matrix.md](07-international-test-matrix.md).
- "Local" rows are not defects: the production site is Saudi. They are the work a second country would need, and each
  must be done behind a company setting so the Saudi default does not change (`AGENTS.md` and the policy: default
  behaviour never changes for existing data).
- A setting-based fix is preferred over a code branch by country. A rule per country is not a design.
