## 1. Version Overview

Company isolation of the registries and the posting endpoints, protected commercial terms and
equipment master fields, a permanent (tamper-proof) GL Posting Log, and posting/diesel/report/
reconciliation fixes. No new end-user module; the release makes the v1.2 feature set safe on
multi-company and multi-role sites.

## 2. Complete Feature Inventory — Verified

Same feature surface as [v1.2.0](v1.2.0.md)/[v1.2.1](v1.2.1.md): **18 DocTypes, 9 reports, 3 app
print formats** + legacy format, Card Settings/roles, rental directions and the customer side,
diesel & transport, accounting dimension, opt-in monthly draft postings. Patches: 22 entries.
New in behaviour (not in file counts): company-scoped endpoints and registries, field protection,
permanent posting log, read-only current project/assignment date with an **optional daily location
sync job (off by default)** — `scheduler_events` daily `card.transfer.sync_equipment_locations_daily`.

## 3. Added — Verified

- Change-reason requirement + kept change history on equipment commercial terms; change history on
  Project Diesel Fill and Equipment Transport.
- Optional daily location-sync job (Card Settings switch, **off by default**).
- Reconciliation shown as **three separate figures**: *invoiced through Card*, *not invoiced
  through Card*, *ERPNext invoices outside Card — to reconcile* (manual-only; nothing is matched or
  relinked automatically).

## 4. Improved — Verified (Security section of the release)

- **Monthly-posting endpoints are company-scoped** (#36): `post_month` / `rebuild_month` refuse a
  company outside the caller's permitted companies before any work.
- **Registries no longer expose other companies** (#23 closed): rows store no figures; the form
  shows figures per company the user may see; list/form/REST visibility limited to parties with
  cards in permitted companies. Earlier change history is kept unchanged as audit history, readable
  by System Manager only; the registries do not track changes (re-enabling is refused).
- **Commercial terms protected** (rates, rate basis, daily hours, direction, parties, contract,
  fuel): permission level 1 — Card Manager writes, Card User reads; Card User no longer creates
  equipment.
- **Equipment control fields protected** (#56): company, linked Asset, unit/components,
  diesel-consumption baselines — Card Manager writes; server-side checks (company immutable once
  used; Asset same-company/not-cancelled/readable; components same-company, not units, not in
  another unit — also on REST row saves).
- **Current project and assignment date are read-only**, synced from the assignment in force today;
  a transfer ending a previous assignment takes effect the day after its date; the free-text
  location is never touched.
- **A unit's card days are checked against the unit's own assignments too.**
- **GL Posting Log is a permanent audit record** (#57): no role can create, edit, delete or share a
  log (System Manager keeps read/report/export); the server refuses even Administrator, shares and
  Custom DocPerms; only CARD's monthly posting creates a log; cancelled and stale logs are kept, so
  a cancelled Card invoice can no longer become amendable by deleting or rebinding its log.
- **Card Settings**: Accounts Manager can save the per-company accounting fields; policy fields
  moved to permission level 2 (System Manager writes).
- On upgrade, an existing monthly-card default print format is kept (#65); new installs default to
  "Card Monthly Card Print".

## 5. Fixed — Verified

- Project names in reports for operational roles (#29, PR #30).
- Diesel reports mark **estimated** vs **recorded** litres; "Actual litres" → "Allocated litres" (#33).
- Monthly posting lines use the source's own cost center when set; split diesel lines state their
  own estimated litres share (#34).
- Clear up-front message when a poster cannot read Items (names the needed role; no rights granted).
- Manual invoices that reuse a deleted Card draft's number can be amended again; amendments of a
  cancelled Card posting remain refused across the whole amendment chain (PR #55).

## 6. Removed — Verified

- **Stored party-wide figures on the supplier/customer registries** (counts, hours, totals) are
  cleared by a patch and no longer maintained — replaced by per-company figures computed for the
  viewing user (#23). Nothing is deleted from the audit history.

## 7. Replaced

See Removed above (stored registry totals → per-company computed display). No API replacement in
this release.

## 8. Simplified

None recorded.

## 9. Breaking Changes — Verified

- Role-capability changes (intentional hardening): Card User no longer creates equipment or writes
  commercial/control fields; only Card Manager writes assignments; no role can mutate GL Posting
  Log; Card Settings policy fields need System Manager.
- Registry list views no longer show party-wide totals (figures are per permitted company on the
  form).
- Custom automation that edited `current_project` / assignment date on the equipment will find them
  read-only.

## 10. Known Limitations — Verified

- Diesel **cost** totals still add recorded + estimated amounts into one figure; only the litres
  are split (#33).
- Rebuilding a monthly posting deletes CARD's draft invoice and creates a new one, which may take
  the same number; edits made on the deleted draft are lost (accounting-enabled sites only).
- Reconciliation GL figures stay VAT-inclusive while card nets are before VAT (shown as separate
  figures since this release).
- Published ≠ deployed: **not deployed to any production site** as of 2026-10-18. A production
  upgrade additionally requires the owner-gated deployment pipeline (rehearsal on a production
  copy, backup validation, PDF-font acceptance) — tracked outside this repo.

## 12. Installation & Upgrade — Verified

- Fresh install: README → Installation (bench or frappe_docker image).
- Upgrading from 1.0.1 runs the `v1_2`, `v1_2_1` and `v1_2_2` patches once each (all
  post-model-sync, idempotent; none writes GL entries, invoices or card amounts). Submitted cards
  get snapshot fields from the equipment's **current** daily hours and fuel policy; empty card
  directions are derived; draft cards re-derived.
- Registries are created/recomputed and their stored figures cleared; change history only counted,
  never deleted. Existing default print format kept.
- Roles Card Manager / Card User are created — assign them. Accounting stays off
  (`enable_accounting = 0`); the `card_equipment` Accounting Dimension is a separate manual step;
  the daily location sync is off.
- **Rehearse the upgrade on a copy of production before deploying it.**
- Downgrade: no down-migrations exist; rollback = restore the pre-upgrade backup.

## 13. Recommended For

- **All new installs** on Frappe/ERPNext v16.5x.
- **Every multi-company site** (first version with registry and endpoint company isolation).
- Sites with mixed roles (operational + accounting) that need the hardened permission model and the
  permanent posting audit log.
- Not for pre-16.50 Frappe (Unknown — use v1.0.1 there).
