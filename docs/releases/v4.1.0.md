# CARD v4.1.0 — 2026-10-25

> Minor release on top of v4.0.0 and the release candidate for the first production go-live (issue
> [#118](https://github.com/SDe-ER/card/issues/118), phases P1–P3). Release PR: this pull request. The
> CHANGELOG section is dated 2026-10-25 (the content cut date). Not tagged yet: the tag is pushed only after the
> release PR is merged (see Evidence).
> Labels: **Verified / Partially Verified / Unknown / Not Supported / Deprecated / Removed**.

## 1. Version Overview

Everything merged after v4.0.0, made ready for a first production site that still runs v1.0.1:

- **Equipment registration (P1)** — owned and rented machines (crushers, generators, dozers, excavators,
  loaders, …), supplier, optional ERPNext Asset link, change history, protected commercial and company fields,
  and, new in this release, **chassis / plate numbers unique per company** (FR-080).
- **Equipment transport (P2)** and **project assignment (P3)** — unchanged in behaviour since v3.0.0/v4.0.0,
  hardened by company-isolation and concurrency fixes (D2, D3, D4, #56).
- **Upgrade rehearsal in CI** from v1.0.1 on the production frappe/ERPNext versions.
- Also shipped, outside the first go-live scope: CARD Mobile (`/cdms`), catalog search, parts fitment phase 2a,
  tool handover and the Tool Custody screen, diesel price lock, period lock.

CARD still writes no GL entry: it creates standard ERPNext documents (drafts) only.

## 3. Added — Verified

- **Unique chassis and plate numbers per company (FR-080, PR #129)**: normalised comparison (case, spaces,
  separators, invisible marks, Arabic-Indic digits), server-side, safe for two saves at once, legacy duplicates
  kept and listed.
- **Upgrade rehearsal workflow (PR #130)**: v1.0.1 → this code on frappe 16.51.1 / ERPNext 16.50.0, synthetic data.
- **CARD Mobile** (`/cdms`, PR #76, #89, #112): operator sign-in, equipment list, equipment needs requests.
- **Catalog search** (FR-076 phase 1, PR #106) and **parts fitment phase 2a** (FR-077, PR #108, #109).
- **Tool handover confirmation and Tool Custody screen** (#113, PR #114, #115, #116).
- **Diesel price lock per company** (FR-002, PR #79) and **period lock on stored dates** (PR #97).
- Card Settings layout (PR #81).

## 9. Breaking Changes — Verified

- A new Card Equipment with a chassis or plate number already used in its company is refused (existing duplicates
  are kept and can be corrected). "Duplicate" no longer copies the two numbers.
- For sites upgrading from v1.x: everything listed as breaking in [v3.0.0](v3.0.0.md) applies (a monthly card needs
  an approved transport for the month).

## 10. Known Limitations — Verified

- CARD Mobile is not tested on real phones; it is not part of the first production go-live.
- Fitment phase 2b (PR #110) is not included.
- Cross-company checks of the go-live scenarios ran in CI only (the QA site has one company).
- Material Requests, Stock Entries and invoices made by CARD are drafts.
- Published ≠ deployed: **not deployed to any production site**.

## 12. Installation & Upgrade — Partially Verified

- `bench --site <site> migrate` runs every pending CARD patch once (from v1.0.1: 21 patches). Rehearsed twice-run
  idempotent with synthetic v1.0.1 data; the production copy rehearsal is a deployment step, not part of the release.
- Before use: set each project's ERPNext cost center; record the first transport of each working machine; give the
  CARD roles to named users (no role is given by the upgrade).
- Rollback: restore the pre-upgrade backup (old code cannot run on the migrated data).

## 13. Recommended For

- Sites on v1.0.1 – v4.0.0 that register equipment, record transports and assign machines to projects.
- **Not** for sites that need CARD Mobile on phones yet (not device-tested).
