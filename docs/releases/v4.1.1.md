## 1. Version Overview

Fixes the `item_query` endpoint gap discovered after v4.1.0 was tagged. Card Manager and other
Tool Custody screen roles could not search for items in the New Handover dialog or the page filter
because those Link fields used Frappe's standard link search, which requires `select: 1` on the
`Item` DocType. v4.1.1 adds a scoped server endpoint that enforces the same authorization check
as the rest of the Tool Custody page (`_check_screen()`), returning only stock items (non-fixed-asset,
enabled). No ERPNext DocPerm change; no data change; no migration. All other v4.1.0 behaviour is
unchanged.

## 5. Fixed — Verified

- **Tool Custody item search works without an ERPNext Item permission (this PR).**
  Added `card.tool_custody.item_query` (GET, `@frappe.validate_and_sanitize_search_inputs`):
  - Gate: `_check_screen()` verifies SCREEN_ROLES + ETC read permission (same check as all Tool Custody endpoints)
  - Filter: `is_stock_item=1, is_fixed_asset=0, disabled=0` enforced server-side
  - `ignore_permissions=True` explicit and justified: the `_check_screen()` call is the authorization
  - No company scoping needed: Items are global in ERPNext; the ETC itself is company-scoped
  - `@frappe.validate_and_sanitize_search_inputs` sanitizes the `txt` parameter
