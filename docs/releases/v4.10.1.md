# CARD v4.10.1 — release candidate (not published)

> Patch release on top of v4.10.0 (PR #282, merged `3401207`): the Additions and deductions table of the Monthly Card
> shows its required date to every user, the form shows the customer-side balance as rows change, and the refusal of
> an unconfigured Adjustment type says how to save the row. Backward compatible: no API, permission, DocType, schema
> or accounting change; one patch that writes users' display settings only.
> **Status: release candidate.** Published only when the owner approves the merge of the release PR and then the tag;
> the date is set then. **Published ≠ deployed** (see [DEPLOYMENTS.md](DEPLOYMENTS.md)).
> Labels: **Verified / Partially Verified / Unknown / Not Supported / Deprecated / Removed**.

## 1. Version Overview

- **Version:** 4.10.1 (`card/__init__.py`, `__version__ = "4.10.1"`).
- **Previous Git release:** v4.10.0 (tag commit `d0614ea`, 2026-11-20). **Last recorded Production version:** v4.10.0

## 5. Fixed — Partially Verified

- **Adjustment date column missing for some users.** Root cause (Production, read-only): a user had saved their own
  columns for the table before v4.10.0, and Frappe shows only a user's saved `GridView` columns. The DocType itself was
  correct (no Property Setter, Custom Field or active Client Script). Fixed by the patch. Verified in CI; not yet seen
  on a real Desk.
- **Customer-side balance did not react on the form.** `card_calc` recalculated only `net_amount` (supplier side). On
  a card rented to a customer the supplier net is 0, so the visible balance did not move until save. Fixed. Verified by
  a local check of the real `card_calc` (13 scenarios; the v4.10.0 code fails the customer-side ones); not yet seen on
  a real Desk.
- **Refused save of a Draft card with additions or deductions.** One refused save (HTTP 417) on Production on
  2026-11-20 21:39 UTC; the response body is not logged, so the exact message is **Unknown**. A dry run of that card's
  validation with every write blocked: dated additions and deductions inside the period pass; the reachable refusals
  are a free-text Adjustment type that is not configured (the site has none; that column was first in the user's saved
  columns) and a date outside the card period. The validation rules are unchanged; the first message now says how to
  proceed. Partially Verified.

## 10. Known Limitations — Verified

- The exact message of the refused save of 2026-11-20 is Unknown (section 5).
- The customer net on a Draft form adds the live rows to the last saved customer amount; the customer amount itself
  updates on save. A new card shows its customer net after the first save.
- A user who keeps a card form open during the upgrade and then resizes a grid column can save the old column list
  again; a reload before editing avoids it.
- A site with no addition/deduction types in Card Settings still refuses a free-text Adjustment type (by design); the
  owner can configure types or reset the table's columns.
- Not verified on a real Desk browser: a post-deployment acceptance check (section 12).

## 11. Compatibility — Partially Verified

16.54.0). The patch uses `frappe.model.utils.user_settings.sync_user_settings` and `clear_user_settings_cache`, read in
the installed frappe 16.56.0 source on Production.

## 12. Installation & Upgrade — Partially Verified

- **Upgrade from v4.10.0:** new code, `bench --site <site> migrate` (runs the one patch), `bench --site <site>
  clear-cache`, restart the app services; no `bench build` (no `public/` or `frontend/` change). Users reload open
  forms.
- **What migrate writes:** only `__UserSettings` rows of `Card Monthly Card` whose saved columns of the adjustments
  table lack the date. No document, amount, GL entry, invoice, payment or permission. A second migrate changes nothing.
- **Post-deployment acceptance (owner, real Desk):** open a Draft card (desktop and phone); the Adjustment date column
  shows; add an addition and a deduction with dates inside the card month; the totals and the side's net change before
  save; save succeeds; a date outside the month is refused with the period in the message; a submitted card's rows stay
  locked.
- **Safe rollback — Verified from source; not runtime-tested.** Target: v4.10.0, commit `d0614ea`. Code only: v4.10.0
  runs on the migrated data (the patch changes display settings only). The added column stays in the saved settings
  (harmless). No GL entry, invoice or Journal Entry is written by the upgrade or the rollback.
