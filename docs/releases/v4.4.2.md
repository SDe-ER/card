# CARD v4.4.2 — 2026-11-09

> Patch release on top of v4.4.1 (PR #178): the A4 supplier statement prints every card of the period and totals
> from the cards only. Backward compatible: no patch, no DocType or schema change, no change to permissions,
> accounting, data or the API.
> Labels: **Verified / Partially Verified / Unknown / Not Supported / Deprecated / Removed**.

## 1. Version Overview

The v4.4.1 check (2026-11-09) showed a supplier whose cards were not yet invoiced printing all-zero ledger totals
on the A4 supplier statement: the v4.4.1 print showed only project and equipment rows and the ledger statement
(opening + period charges − payments = closing), so work done but not yet invoiced did not appear in the totals.
The owner asked (2026-11-09) for:

- every row of the period in the print: project, equipment as a sub-heading and every card with its shift,
  numbered, whatever their count;
- totals from the cards only: the cards net for the period and, when positive, the work done not yet invoiced
  through CARD (before VAT; no VAT is computed). The ledger lines are no longer printed and no footnote is
  printed (the server note still prints only when the period has no rows, as in v4.4.1);
- a last line "Issued by the electronic system of <company>" (the company comes from the report filter; nothing
  hard-coded);
- the period printed as full dates: first day of the start month to the last day of the end month, as the
  report computes it (the end month and year default to the start ones);
- font Noto Sans Arabic: the installed font first (server PDF), the app's bundled copy (`/assets/card/fonts`) as a
  fallback for a browser without it.

Why a patch version: a correction of the v4.4.1 print output of one report; no new capability, no schema change,
no change to the report data.

## 3. Added

Nothing added as a capability. The issued-by footer and the three msgids are additions to an existing print.

## 4. Improved

- The A4 supplier statement shows the work of the period card by card and the cards net, also for suppliers
  whose cards are not yet invoiced (FR-089; PR #178).
- The period prints as full dates instead of month/year.

## 5. Fixed — Partially Verified

- A supplier with cards not yet invoiced no longer prints all-zero totals: the printed totals come from the cards
  of the period (FR-089; PR #178). Shown by the template and `test_supplier_statement_print.py`; a print of the
  same supplier on a real site after the deploy is not part of the release evidence (section 10).

## 6. Removed

- The ledger lines (opening balance, period charges incl. VAT, payments, closing balance) are no longer printed on
  the A4 supplier statement (Owner request 2026-11-09). The screen report and the ERPNext ledger keep them; no
  data is removed.

## 7. Replaced

- The printed totals block of the A4 supplier statement: ledger statement → cards net and, when positive, work
  done not yet invoiced through CARD (before VAT).
- The printed project/equipment rows → every row of the period, cards included.
- The print font stack: `"Cairo", "Noto Sans Arabic", …` → `"Noto Sans Arabic"` (installed) then the bundled
  copy.

## 8. Simplified

- The printed totals have at most two lines (cards net; not yet invoiced) instead of four ledger lines.

## 9. Breaking Changes — Verified

None. No schema, permission, accounting, data or API change; the print format keeps its name; the report summary
is unchanged. A reader who used the printed ledger balance of the A4 statement must use the screen report or the
ERPNext ledger.

## 10. Known Limitations — Verified

- **Published ≠ deployed.** Deployment of 4.4.2 to any site is a separate, site-verified fact (section 14).
- The PDF button of the A4 supplier statement still renders with wkhtmltopdf: frappe `report_to_pdf`
  (`frappe/utils/print_format.py`) always uses wkhtmltopdf for report prints, so that PDF can still break Arabic
  letter joining. The browser Print of the report uses the installed or bundled Noto Sans Arabic; use it for
  Arabic.
- The printed totals no longer show the supplier's ledger balance. "Work done not yet invoiced" is before VAT; no
  VAT is computed, and it prints only when positive.
- A period with many cards prints on several A4 pages; a print of a real long period: **Unknown** until the
  post-deploy check (section 12).
- As in v4.4.1: names stored in the data print as stored; in a language without a CARD catalogue the
  CARD-specific labels print in English; choose Landscape in the PDF dialog of the A4 supplier statement.
- Rolling back the code alone does not restore the v4.4.1 A4 print format (section 12).

## 12. Installation & Upgrade — Partially Verified

`bench --site <site> migrate` runs no new patch (`card/patches.txt` unchanged) and changes no DocType. It
re-imports only the standard Print Format `Equipment Supplier Statement A4` (file `modified` 2026-11-09 23:00,
newer than the v4.4.1 row). The other CARD print formats and the Print Format fixture are unchanged. It writes no
value to cards, transports, fills, receipts, postings, GL Posting Logs or settings, and no GL entry.

Restart the web and background workers after the code update (normal for an image deploy). Compile the CARD
translations (`ar`) into the image as in previous deployments; without them the new labels print in English.

**Post-deploy check (required):** print the A4 supplier statement with the browser Print for a supplier with
cards not yet invoiced and for a supplier with invoiced cards; check that every card prints with its shift, the
cards net and the not-yet-invoiced line (when positive), the full From/To dates, the issued-by line with the
company name, and the Arabic font.

**Rollback statement — Partially Verified** (the frappe import rules are those recorded for v4.4.0 and v4.4.1,
read in frappe `version-16` source; the commands were not rehearsed on a site).

- Last stable version: **v4.4.1** (runs on Production since 2026-11-09).
- Data: v4.4.1 code runs on the v4.4.2 database. There is no schema change and the report data is unchanged.
- Print format: checking out v4.4.1 and running `bench migrate` does **not** restore the v4.4.1
  `Equipment Supplier Statement A4`, because its file (`modified` 2026-11-09 16:10) is older than the v4.4.2 row
  and `import_file_by_path` skips it unless `force` is set. Until it is re-imported the A4 format keeps the v4.4.2
  template, which works with the v4.4.1 report (same summary keys).
- Steps, after the owner's approval for the rollback and a verified backup:
  1. Deploy the v4.4.1 code (image) and restart the workers.
  2. `bench --site <site> migrate` (changes no CARD data).
  3. Re-import the A4 format from the v4.4.1 file with `force`:
     ```
     bench --site <site> execute frappe.modules.import_file.import_file_by_path \
       --kwargs '{"path": "<bench>/apps/card/card/card/print_format/equipment_supplier_statement_a4/equipment_supplier_statement_a4.json", "force": True}'
     ```
     Write `True` (Python), not `true`.
  4. Print the statement once to check it renders.
- Alternative: restore the pre-upgrade database backup, only while no data was entered after the backup;
  otherwise use the forced re-import, which touches only that Print Format row.
