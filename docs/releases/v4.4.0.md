# CARD v4.4.0 — 2026-11-09

> Minor release on top of v4.3.0: the CARD print formats take the owner-approved standard Frappe print style and
> print in the print language with its page direction; the A4 supplier statement moves its totals under the
> amount columns and hides empty Additions/Deductions columns. New Jinja method
> `card.print_utils.card_print_is_rtl`. Backward compatible: no patch, no DocType or schema change, no change to
> permissions, accounting, data or the API.
> Labels: **Verified / Partially Verified / Unknown / Not Supported / Deprecated / Removed**.

## 1. Version Overview

Every CARD print now looks like a standard ERPNext print: white page, the Frappe v16 print greys as literal
colours, the company name above the title, the details as label/value lines, a row table with a grey header, the
totals at the end side of the page and signature lines at the bottom. This covers the five document print
formats (`Card Monthly Card Print`, the fixture `كارت تشغيل شهري`, `Equipment Transport Print`,
`Project Diesel Fill Print`, `Tool Handover Receipt`) and the Report Print Format `Equipment Supplier Statement A4`.
Each print follows the print language: every fixed text is translated, and the page is right to left for Arabic
(and the other right-to-left languages, plus Urdu) and left to right otherwise. The fixture `كارت تشغيل شهري` no
longer forces English. What the prints contain (which blocks and sides print, sums and nets) is unchanged; only
the supplier statement print drops the equipment number, rate type and rate columns (the screen report keeps
them).

Why a minor version: new display behaviour (print language and direction, dynamic columns) and a new Jinja
method, backward compatible, no schema change.

## 3. Added — Verified

- Jinja method `card.print_utils.card_print_is_rtl` (PR #172). Display helper only; not a whitelisted endpoint.

## 4. Improved — Verified

- Standard print style and print language for the five CARD document print formats (FR-055, FR-045; PR #172).
- Standard print style for the Equipment Supplier Statement A4: totals under the amount columns, dynamic
  Additions/Deductions columns, translated statement type (FR-089; PR #171).
- Print formats follow the print language, so FR-083's "print formats are Arabic by design" no longer holds
  (FR-083 note updated).

## 5. Fixed — Verified

- Fixed before release, inside the release scope: the Friday row condition of the monthly card prints is
  parenthesised (Jinja refused it; found by the upgrade rehearsal of PR #172; fix `de3643d`), and the statement
  totals heading uses the CARD-only msgid "Statement totals" so frappe's generic "Totals" translation is not
  overridden (fix `e52d43f`, PR #171). No defect of v4.3.0 is fixed by this release.

## 6. Removed

Nothing removed. The equipment number, rate type and rate columns are no longer printed on the A4 supplier
statement; the screen report keeps them and no data is removed.

## 7. Replaced

- The v4.3.0 print layouts of the six formats are replaced by the standard print style (same data).

## 8. Simplified

- The monthly card print shows additions/deductions, card totals and the settlement of each billed side in three
  columns, so a sub-rental card with adjustments fits one A4 page (template change; real PDF check: section 10).

## 9. Breaking Changes — Verified

None. No schema, permission, accounting, data or API change; the print formats keep their names. A site that
relied on the fixture `كارت تشغيل شهري` always printing in English now gets the user's language (choose English in
the print dialog to keep it).

## 12. Installation & Upgrade — Partially Verified

`bench --site <site> migrate` runs no new patch (`card/patches.txt` unchanged since v4.2.2) and changes no
DocType. It re-imports the five standard Print Formats (`Card Monthly Card Print`, `Equipment Transport Print`,
`Project Diesel Fill Print`, `Tool Handover Receipt` with file `modified` 2026-11-09 14:00,
`Equipment Supplier Statement A4` with 2026-11-09 13:30), because their files are newer than the database rows,
and the Print Format fixture `كارت تشغيل شهري` (html and css replaced, `default_print_language` cleared from
`en`). It writes no value to cards, transports, fills, receipts, postings, GL Posting Logs or settings, and no GL
entry.

`hooks.py` adds a Jinja method, so the web and background workers must restart after the code update (normal for
an image deploy). Compile the CARD translations (`ar`) into the image as in previous deployments; without them the
Arabic print shows the CARD labels in English.

**Rollback statement — Partially Verified** (the frappe import rules below are read in frappe `version-16`
source, 16.55.2; the commands were not rehearsed on a site).

- Last stable version: **v4.3.0**.
- Data: v4.3.0 code runs on the v4.4.0 database. There is no schema or data change, and no value written by 4.4.0
  that v4.3.0 reads differently.
- Print formats: checking out v4.3.0 and running `bench migrate` does **not** restore the five v4.3.0 standard
  Print Formats. `frappe.modules.import_file.import_file_by_path` skips a non-DocType file whose `modified` is
  the same as or older than the database row unless `force` is set, and the v4.3.0 files are older than the
  v4.4.0 rows.
- The four restyled DocType formats and the v4.4.0 fixture call `card_print_is_rtl()`. v4.3.0 does not register
  that Jinja method, so after a code-only rollback these prints fail to render until the v4.3.0 versions are
  back. `Equipment Supplier Statement A4` uses frappe's own `is_rtl()` and the same report data (the report `.js` is
  unchanged), so it is expected to keep rendering in the v4.4.0 style (Unknown: not tested under v4.3.0 code).
- The fixture `كارت تشغيل شهري` returns to its v4.3.0 content (with `default_print_language` `en`) on that
  migrate: `frappe.utils.fixtures.sync_fixtures` imports fixture files with `force=True`, so an older `modified`
  does not block it.
- Steps, after the owner's approval for the rollback and a verified backup:
  1. Deploy the v4.3.0 code (image) and restart the workers.
  2. `bench --site <site> migrate` (restores the fixture; changes nothing else).
  3. Re-import each of the five standard formats from the v4.3.0 files with `force`:
     ```
     bench --site <site> execute frappe.modules.import_file.import_file_by_path \
       --kwargs '{"path": "<bench>/apps/card/card/card/print_format/<name>/<name>.json", "force": True}'
     ```
     for `<name>` = `card_monthly_card_print`, `equipment_transport_print`, `project_diesel_fill_print`,
     `tool_handover_receipt`, `equipment_supplier_statement_a4`. `bench execute` evaluates `--kwargs` as a
     Python expression, so write `True` (JSON `true` is not a Python name). The import writes the file's own
     `modified` back to the row, so a later upgrade to 4.4.0 re-imports the formats again.
  4. Open each print once to check it renders.
- Alternative: restore the pre-upgrade database backup. It also restores the old formats, but only while no data
  was entered after the backup; otherwise use the forced re-import, which touches only Print Format rows.

## 13. Recommended For

- Every site on v4.3.0 that prints CARD documents or the supplier statement and wants the standard print style
