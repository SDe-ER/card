# CARD v4.5.0 — 2026-11-09

> Minor release on top of v4.4.3 (PR #182): settlement phase 1. Backward compatible: no patch, no DocType or schema
> change, no GL write. One new POST API method and one new read-only report.
> Labels: **Verified / Partially Verified / Unknown / Not Supported / Deprecated / Removed**.

## 1. Version Overview

Some supplier cards are recognised by hand with a Journal Entry (expense debit, supplier credit) instead of a
Purchase Invoice. Before this release CARD did not see such an entry: the statement showed those cards as "not
invoiced through CARD", and the monthly posting (when accounting is enabled) would have invoiced them a second time.
The owner approved (2026-11-09) a controlled exception for historical supplier cards, the FIFO default for paid
amounts, and a two-phase plan; this release is phase 1.

Why a minor version: a new capability (the link and the report), with no breaking change.

## 2. Complete Feature Inventory — Verified

Everything in [v4.4.3](v4.4.3.md) is present (code at the tag). Changes:

| Component | Change |
|---|---|
| `card/gl/journal_link.py` (new) | `link_accrual_journal` (`methods=["POST"]`): an accountant (Accounts Manager, Accounts User, System Manager, with read and submit right on the entry) links a submitted ordinary Journal Entry that credits exactly one supplier to submitted supplier monthly cards of the same company and supplier; the credit less the entry's tax rows must equal the cards' net (a difference only with an accepted reason). A Linked GL Posting Log of type Journal Entry reserves the cards. `before_cancel` on Journal Entry frees them |
| `card/reconciliation.py` | `cards_invoiced` counts Journal Entry links as recognised (no year window on those links) |
| `card/card/doctype/gl_posting_log/gl_posting_log.py` | A Linked Journal Entry log must be a submitted supplier accrual |
| `card/card/report/card_settlement_status/` (new) | Read-only Script Report (System Manager, Accounts Manager; ledger access required): per card the recognising document, share, paid, credit notes and remaining from the Payment Ledger Entry, oldest first; payments of the party not allocated to a document up to the end date |
| `card/card/sidebar/card_reports/card_reports.json` | Sidebar link to the report |
| `card/locale/ar.po`, `card/locale/main.pot` | Arabic for every new message |
| `card/tests/test_settlement_phase1.py` (new) | Link, reservation, refusals, VAT rows, cancel, ledger-based status, FIFO, permissions, POST only |

## 10. Known Limitations — Verified

- **Published ≠ deployed.** Deployment of 4.5.0 to any site is a separate, site-verified fact (section 14).
- The link is an API method; there is no Desk button yet.
- Settlement documents, payment drafts and the owner current account (phase 2) are not in this release.
- The report reads the Payment Ledger Entry: a payment that is not allocated to the recognising document (for
  example a bank journal entry without a reference) shows as "not allocated" until an accountant allocates it with
  the standard Payment Reconciliation.
- Accounting (`enable_accounting`) stays as configured on the site; this release does not enable it.

## 12. Installation & Upgrade — Partially Verified

`bench --site <site> migrate` runs no new patch and changes no DocType. It adds the Report "Card Settlement Status"
and updates the "Card Reports" sidebar. It writes no value to cards, postings or settings, and no GL entry. Restart
the web and background workers after the code update. Compile the CARD translations (`ar`) into the image.

**Post-deploy check (required):** open Card Settlement Status for one supplier as an Accounts Manager and check
that it loads with the ledger amounts. No link is made by the check.

**Rollback statement — Partially Verified.**

- Last stable version: **v4.4.3**.
- Data: the v4.4.3 code runs on the v4.5.0 database. Linked Journal Entry logs stay as data; the old code ignores
  them, so linked cards count as not invoiced again. Keep accounting disabled, or cancel the links (cancel the
  journal entry or ask for an unlink) before a rollback.
- The report row stays in the database after a code rollback; it cannot run without the v4.5.0 code.

## 13. Recommended For
