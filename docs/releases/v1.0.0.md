## 1. Version Overview

First release of CARD as a standalone Frappe v16 app, at **exact production parity** with the
pre-existing production-native CARD setup (equipment DocTypes + monthly-card workflow + two script
reports + Card workspace). The client/server scripts of the legacy setup were converted into an app
with controllers, reports, fixtures and an idempotent installer. There is **no accounting posting,
no customer side, no diesel/transport and no i18n layer** in this version — those arrive in v1.2.0.

## 10. Known Limitations — Verified

- The packaged `__version__` is `0.0.1` (bench scaffold default) while the tag is `v1.0.0`;
  intentional for this release, reconciled from v1.0.1 onward.
- Fails `bench migrate` on **Frappe ≥ 16.51** (Workspace `module` became mandatory) — fixed in
  v1.0.1. On 16.50+, the new desk `Sidebar` is not curated — folded in v1.0.1.

## 11. Compatibility — Verified

| Requirement | Value |
|---|---|
| Frappe / ERPNext | v16 — validated on 16.33.0 and 16.36.1. **Not Supported:** Frappe ≥ 16.51 (see limitation above; use v1.0.1) |
| Python | ≥ 3.14 (`pyproject.toml`) |
| Required apps | `erpnext` only; no other custom app |

## 12. Installation & Upgrade — Verified

- Fresh/legacy site: `bench get-app … && bench --site <site> install-app card` — on a legacy site
  with the pre-existing setup use `install-app card --force` (the installer adopts the existing
  Module Def).
- Docker: when baked into an image whose runtime `sites/assets` is a volume symlink, card's static
  files must be materialized into the image's bench-root `assets/card` (README of this tag,
  *Baked into a Docker image*).
- Downgrade: no earlier app version exists. Rollback = uninstall + restore backup.

## 13. Recommended For

- Historical reference only. Any site on Frappe 16.33–16.50 that wants exactly the original
  monthly-card workflow should use **v1.0.1** instead (same features, migrate-safe on 16.5x).
